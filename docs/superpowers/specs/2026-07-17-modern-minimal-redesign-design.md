# 小米笔记博客极简现代改版设计

## 目标

将现有蓝紫渐变、常规卡片式博客界面升级为具有现代编辑感的个人笔记站。界面以内容为中心，通过大留白、准确排版、黑白灰层级和少量钴蓝品牌色建立辨识度，同时保留现有同步、搜索、分类、密码保护、笔记管理和设置能力。

## 设计原则

- 大留白优先，避免渐变背景、装饰性光斑和厚重面板。
- 黑、白、灰承担绝大部分界面，钴蓝仅用于品牌识别、当前状态、焦点和关键反馈。
- 不使用等宽卡片墙。文章列表采用轻微错位的文字索引，但仍保持稳定的阅读顺序。
- 动效提供层次和反馈，不抢夺阅读注意力，并完整支持 `prefers-reduced-motion`。
- 桌面端强调编辑感和空间节奏；移动端恢复紧凑、安全的单列结构。

## 视觉系统

### 色彩

- 页面背景：近白色 `#fafafa`。
- 主文字：近黑色 `#111111`。
- 次要文字：中性灰，按信息层级使用约 `#737373` 至 `#a2a2a2`。
- 分隔线：浅灰色，默认约 `#dedede`。
- 品牌色：钴蓝，默认约 `#275df5`。
- 危险操作继续使用现有语义红色，不用品牌蓝替代。

所有颜色通过 CSS 变量集中定义，组件不得散落硬编码主题值。

### 排版

- 界面与标题使用清晰的现代无衬线字体栈，优先使用系统字体，不额外引入远程字体。
- 首页主标题使用紧凑字距和显著字号，形成视觉锚点。
- 正文保持舒适行高与窄阅读宽度，避免首页展示样式侵入文章内容。
- 分类、日期、数量等元信息使用小字号和适度字距，与正文明确区分。

### 线条与表面

- 使用单像素中性分隔线构造结构。
- 首页文章不使用独立卡片背景、圆角容器或常驻阴影。
- 弹窗、菜单和表单可使用轻薄边框与极弱阴影，以保证浮层关系。
- 圆角保持克制；按钮以直角或小圆角为主。

## 页面结构

### 全局导航

- 左侧显示可配置站点名称和一个钴蓝品牌圆点；自定义 Logo 存在时使用 Logo 替换圆点。
- 右侧保留设置与同步入口。
- 同步按钮使用近黑底白字；同步中通过图标旋转和文案变化表达状态。
- 移动端隐藏非必要文字，仅保留可辨识操作。

### 首页

- 首屏由品牌上标、主标题、站点描述和笔记数量构成双列布局。
- 搜索与分类筛选放在首屏和列表之间，搜索框表现为带底线的轻量输入区域。
- 笔记以编号文字索引呈现，每行包含标题、分类、日期和进入箭头。
- 相邻条目可有轻微水平错位，打破机械列表感；错位不得改变 DOM 阅读顺序。
- 分类筛选、搜索、空状态、锁定状态和管理员操作必须继续可用。
- 管理员的编辑、密码和删除操作通过低干扰的行内菜单呈现，不破坏访客视图。

### 笔记详情

- 使用窄版居中阅读栏。
- 顶部保留返回入口、日期、分类和管理员菜单。
- 标题、摘要和正文之间使用留白与细线分区。
- Markdown 内容延续现有解析与安全策略，仅调整排版、代码块、引用、图片和列表的视觉样式。
- 受保护笔记的验证流程与当前接口保持不变。

### 设置和密码相关界面

- 设置、管理员认证、站点密码、分类密码和笔记密码弹窗统一采用近白表面、轻薄边框和简洁标题区。
- 输入框以底线或轻边框表现，聚焦时使用钴蓝。
- 保存、确认使用近黑主按钮；次要操作为文字或描边按钮；删除继续使用危险色。
- 不修改现有字段、验证、认证和保存行为。

### 加载、空状态与错误状态

- 加载状态使用 React Bits 风格的简洁文字渐显或细线进度反馈。
- 空状态使用排版与编号语言，不引入大幅插画。
- 错误继续通过现有 Sonner 提示，并统一为新主题的轻量样式。

## 动效与组件来源

- React Bits：用于页面标题分段入场、列表滚动渐显和内容切换；组件本地化后纳入项目目录。
- Aceternity UI：仅借鉴或本地化轻量内容过渡与细线/遮罩效果，不采用大面积动态背景。
- Uiverse.io：用于按钮、输入框、加载状态的微交互细节，改写为统一设计令牌。
- Motion 依赖已存在，统一作为动画实现基础，不新增重复动画库。
- 入场动画约 300–500ms，悬停反馈约 150–220ms；禁止持续晃动、强视差和循环装饰动画。
- `prefers-reduced-motion: reduce` 时关闭位移、分段和滚动动画，只保留必要状态变化。

## 组件边界

- 新增主题令牌与基础动效工具，页面组件只消费语义变量。
- `Header` 负责全局品牌和操作，不负责页面 Hero。
- 首页 Hero、搜索筛选和笔记索引拆分为独立组件，避免继续扩大 `NotesList`。
- 笔记索引项只负责展示和触发既有回调；数据读取、筛选、编辑和删除仍由现有业务层控制。
- 详情页阅读头部与正文排版拆分，认证和数据请求逻辑保持原位。
- 对话框共享统一的表面、字段和动作样式，不重写现有认证流程。

## 数据流与兼容性

- 不修改 API、数据结构、路由、同步逻辑、密码验证、管理员 Session 或本地解锁状态。
- 站点名称、描述、Logo、分类和笔记数据继续来自现有设置与接口。
- 无 Logo、无描述、无笔记、长标题、长分类名和大量笔记均需有稳定布局。
- 桌面端断点以上使用编辑式布局；移动端保持单列，不保留会导致横向溢出的错位。

## 测试与验收

- 现有 Node 测试必须全部通过。
- Vite 生产构建必须成功。
- 为新增的纯逻辑或可测试状态补充聚焦测试，不为纯 CSS 动画制造脆弱快照。
- 手工验证桌面端和移动端：首页加载、搜索、分类筛选、进入详情、返回、同步、设置、编辑、删除、各类密码弹窗和错误提示。
- 验证键盘焦点、对比度、可见标签和减少动态效果偏好。
- 验收标准是：功能行为保持一致；视觉与确认 Demo 一致；页面无横向滚动；白天环境下文字清晰；动画不阻碍操作。

## 非目标

- 不修改服务端接口和存储格式。
- 不增加深色模式、主题切换器或用户自定义配色。
- 不引入远程图片、远程字体或重型视觉依赖。
- 不重写 Markdown 解析、同步逻辑、认证逻辑或路由结构。
